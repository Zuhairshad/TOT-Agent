# Rules review (CLAUDE.md vs the repo)

Reviewed on 2026-10-30 against the working tree (nothing is committed yet). Status: **OK** = the
rule holds and there is evidence; **BREAKS** = the rule was broken (fixed here, see "Fixed"); **GAP** =
not a break, but something is missing, unverifiable in the sandbox, or needs your decision.

Automated guards for the greppable rules live in `scripts/rules.test.ts` (runs in `pnpm test`).

## Rule 1: polite scraping

| Rule                                            | Status         | Evidence                                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scheduled runs: max 1 per hour                  | OK             | `.github/workflows/scrape.yml:6` is the only schedule (`7 * * * *`), checked by `scripts/rules.test.ts`. `scrape.yml:14-17` serialises runs (`concurrency`, no cancel). Nothing else in the repo starts the scraper.                                                                                                                   |
| Manual runs cannot exceed 1 per hour            | GAP            | `scrape.yml:7` (`workflow_dispatch`) lets a human start extra runs, and a manual run plus the scheduled one in the same hour would be 2 runs. Nothing in code can see "the last run was 20 minutes ago". **Your decision**: accept it (you are the only person with access, and `dry_run` still opens the site), or add a guard later. |
| Max 2 result pages per keyword (hard cap)       | OK             | `packages/scraper/src/run.ts:19` (`MAX_PAGES_PER_KEYWORD = 2`) is the loop bound at `run.ts:162`; page 2 only after a full page 1. Test: `test/run.test.ts` "hard-caps page loads at 2 per keyword" (3 keywords, every page full, exactly 6 loads).                                                                                    |
| 3-8 s random wait between page loads            | OK             | `src/delay.ts:11` (`POLITE_DELAY`), applied in the single navigation function `run.ts:130-133`; every page load goes through it. `explore.ts` uses the same delay (`explore.ts:30-37`).                                                                                                                                                |
| Delay floor cannot be lowered for the real site | BREAKS (fixed) | `delayRangeFromEnv` honours `TOT_MIN_DELAY_MS` when the test switch `TOT_ALLOW_FAST_DELAYS=1` is set, so a stray env var could have made the real run impolite. Now `site.assertPoliteDelays` (`src/site.ts`) throws for the real host in `run.ts:101` and `explore.ts`. Tests: `test/site.test.ts`, `test/run.test.ts`.               |
| Normal Chromium                                 | OK             | `src/browser.ts:7` returns only `{ headless: true }` (+ optional `executablePath`); no args, no context options except `storageState`. Test: `test/browser.test.ts`.                                                                                                                                                                   |
| Total load per run is bounded                   | OK             | 11 keywords (`keywords.json`) x 2 pages = at most 22 page loads + 1 login, about 2-3 minutes with the waits. `timeout-minutes: 10` at `scrape.yml:25`.                                                                                                                                                                                 |
| Run once without an error loop                  | GAP            | While `SITE_CONFIGURED = false` (`site.ts:13`) every scheduled run exits 1 immediately without touching the site (harmless, but it burns a minute and shows a red run every hour). Keep the workflow disabled (Actions > Scrape > Disable) until go-live step "flip SITE_CONFIGURED". See `docs/go-live-checklist.md`.                 |
